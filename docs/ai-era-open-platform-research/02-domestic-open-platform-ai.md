## 一、执行摘要（先出结论）

1. **国内三大协作平台已全面拥抱 MCP 作为 AI 接入的统一通道**：钉钉（OpenAPI MCP + MCP 广场 + AI 能力中心）、飞书（OpenAPI MCP + 智能伙伴创建平台 Aily）均已官方发布 MCP 能力；企业微信以"智能客服/AI 应用"生态为主（领域知识，需复查）。
2. **共同模式**：将**现有 OpenAPI 封装为 MCP Server**（面向 AI 场景优化语义），并配套**低代码/零代码的 Agent 应用搭建平台**（钉钉 AI 助理、飞书 Aily）。
3. **对 open-app 的含义**：国内头部已验证"开放平台 AI 化 = OpenAPI → MCP 封装 + Agent 应用市场"的路径，open-app 可参照执行，且**治理/审批 AI 化是差异化机会点**（三家都还比较浅）。

## 二、钉钉开放平台 AI 化

### 2.1 OpenAPI MCP（官方，核心动作）

| 维度 | 现状（官方文档） |
|------|----------------|
| 形态 | **钉钉 OpenAPI MCP**——遵循 MCP 协议的标准中间件，扮演"连接 AI 工具（Cursor、Claude 等）与钉钉开放平台 API 的桥梁" |
| 接入方式 | 支持 **SSE 或 Config** 方式快速为 AI 助理接入 MCP 技能；支持在助理市场安装预置 MCP 技能 |
| 部署 | 官方开源 `open-dingtalk/dingtalk-mcp`（GitHub），通过环境变量（DINGTALK_Client_ID/Secret/ACTIVE_PROFILES）配置，可按需激活 MCP 服务 |
| 集成目标 | 让 Cursor、Claude、Claude Code 等 AI 工具直接通过自然语言操作钉钉能力 |

### 2.2 AI 能力中心与 MCP 广场（官方）

- **mcp.dingtalk.com（钉钉 AI 能力中心）**：一站式 AI 能力平台，汇聚 **MCP 服务、AI 技能、智能 Agent**。
- **钉钉 MCP 广场**：一站式集成上千款企业应用，零代码构建个性化工作流，AI 智能推荐（官方宣传语）。
- **AI 助理（Agent）**：汇集钉钉 AI 产品能力（智能文档、智能会议、智能应用），已有超 50 家企业加入（官方宣传，2026 数据需复查）。

### 2.3 第三方能力接入方式（领域知识 + 官方佐证）

- 通过 MCP 技能：第三方以 MCP Server 形式接入钉钉 AI 助理 → **与 open-app 能力开放形式 R1~R4 直接对应**。
- 通过应用市场/助理市场：预置技能的生态分发。

## 三、飞书开放平台 AI 化

### 3.1 OpenAPI MCP（官方）

| 维度 | 现状（官方文档） |
|------|----------------|
| 形态 | 飞书开放平台 MCP 能力，**基于 OpenAPI 面向 AI 场景封装优化**，将传统接口调用升级为**工具化能力**，提升大模型调用准确性、速度与效果 |
| 能力范围 | **当前支持云文档场景**，后续将开放多维表格、日历等更多场景（官方文档原文） |
| 目标 | AI 可自然理解业务语义，低成本完成数据读写与业务操作 |
| 社区 | 大量第三方飞书 MCP（文档、多维表格、知识库读写）已出现（GitHub/MCP 目录） |

### 3.2 智能伙伴创建平台 Aily（官方）

- **定位**：企业级 AI 应用开发平台，提供 **AI 技能编排、知识数据处理** 等功能，帮助企业构建和发布 AI 应用。
- **能力**：支持豆包大模型和企业自选模型；上百个开箱即用的 AI 应用；提供标准 API、SDK 与高频场景对接。
- **交互**：开发者可搭建 AI 应用，用户通过自然语言交互（访问数据、更新信息、获取商业洞察）。

### 3.3 对 open-app 的启示

- 飞书将 MCP 能力**按场景渐进开放**（先云文档，再多维表格、日历）——open-app 可参照：先选 IM/Meeting 高频场景试点。
- Aily 的"AI 技能编排 + 知识数据 + 低代码应用"三位一体，对应 open-app 未来"Agent 应用编排"的产品形态。

## 四、企业微信开放平台 AI 化

> ⚠️ 本节主要基于领域知识，官方一手文档采集受限（搜索被限流），需在可访问国内站点的环境复查。

| 维度 | 现状（领域知识） |
|------|----------------|
| AI 形态 | 以**智能客服、智能表单、AI 应用**为主；微信生态 AI 应用（公众号/小程序 + 大模型） |
| 开放能力 | 企业微信 API（消息/通讯录/客户联系/智能客服）与微信生态打通 |
| MCP 进展 | 未见官方统一 OpenAPI MCP（截至领域知识时间），第三方 MCP 适配零散 |
| 定位差异 | 腾讯系 AI 重心在元宝 + 微信生态；企微更多是"AI 应用运行场所"而非"AI 能力开放者" |

**判断**：企微在"开放平台 AI 化"上落后于钉钉/飞书一个身位；对 open-app 而言，**对标重点是钉钉和飞书**。

## 六、对 open-app 的启示（对应 G1/G3）

1. **行业趋势验证（G1）**：✅ 国内头部（钉钉/飞书）正在走"能力开放平台 → Agent 开放平台"路线，**共识确认**。统一动作是 **OpenAPI → MCP 封装**。
2. **AI 开发者门户形态（G3）**：= MCP 服务市场/广场 + 低代码 Agent 搭建平台 + 预置 AI 技能。open-app 的 `market` 能力管理模块（README §1.1 渠道网络）天然可升级为"MCP 服务市场"。
3. **差异化机会点**：三家平台**审批/权限 AI 化都浅**。open-app 现有治理骨架（动态审批流 + 权限中心 + 40 表）若实现"Agent 动态授权、敏感度驱动审批"，将成为国内独特竞争力（对应 G4）。
4. **对齐动作**：open-app 应发布**官方 OpenAPI MCP**（覆盖 IM/Meeting/CloudBox/Contact/Mail/Drive/Bot），按场景渐进开放，并对标钉钉/飞书的接入体验（SSE + Config + 市场分发）。
