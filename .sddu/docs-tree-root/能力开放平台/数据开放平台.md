## 1. 业务概述

| 属性 | 值 |
|------|-----|
| **业务定位** | open-app 上层应用（阶段 2） |
| **对应 Feature** | DATA-OPEN-001（数据开放平台） |
| **状态** | 🟡 suspended（搁置） |
| **业务角色** | 将 XX 通讯平台的业务数据资产（封闭在平台内部）通过标准流程开放给企业内其他系统消费 |

**业务说明**（spec §2）：XX 通讯平台积累了大量业务数据资产，但当前这些数据被封闭在平台内部，无法被企业内其他系统有效消费和利用。数据开放平台解决：接入效率低、三方平台接入成本高、业务创新受阻。

**与能力开放平台的关系**（discovery §5.4）：

| 维度 | 关系说明 |
|------|---------|
| **定位** | 能力开放平台是基础设施，数据开放平台是上层业务应用 |
| **依赖** | 数据开放平台依赖能力开放平台的能力（API/事件通道、权限管理、审批管理等） |
| **建设顺序** | 能力开放平台先构建（阶段 1），数据开放平台后构建（阶段 2） |
| **权限模型** | 数据对象关联到权限后复用统一权限管理和审批管理 |

> 💡 **关键理解**：数据开放平台是能力开放平台的"消费方"，而非"超集"。

## 2. 核心功能（spec 规划）

| 功能域 | 功能 | 优先级 |
|--------|------|:----:|
| **数据注册** | 数据对象注册 | Must Have |
| **动态审批** | 基于敏感度的动态审批链（L1-L5 敏感度分级） | Must Have |
| **数据上架** | 数据服务上架 | Should Have |
| **订阅申请** | 数据订阅申请 | Must Have |
| **消费数据** | 数据消费（api-server DataQueryController） | Should Have |
| **审计监控** | 数据消费审计与监控 | Could Have |

**核心流程**：数据注册 → 动态审批 → 数据上架 → 订阅申请 → 消费数据 → 审计监控
