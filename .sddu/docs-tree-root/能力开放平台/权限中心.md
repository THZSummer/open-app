## 1. 业务概述

| 属性 | 值 |
|------|-----|
| **能力类型** | 平台本身能力 · 基础能力 |
| **对应 Feature** | CAP-OPEN-001（能力开放平台） |
| **状态** | ✅ validated（全流程完成） |
| **业务角色** | 统一权限模型：权限资源独立抽象，支持多类型资源（API/事件/回调/数据），是 API/事件/回调/连接器开放共同依赖的鉴权底座 |

**业务说明**（G1）：提供统一的权限管理底座。支持基于权限资源（API/事件/数据等）创建权限并关联到资源，申请权限即代表申请了权限关联的资源；衍生的权限可授予开放应用（业务应用、个人应用）。

**核心机制**：
- **权限资源抽象**：权限（permission）指向具体资源（resource_type + resource_id 多态），如 API、事件、回调
- **订阅关系**：应用订阅权限（subscription → permission），订阅即获得该资源的消费权
- **Scope 授权**（G7）：用户授权应用通过 scope 访问自己数据（user_authorization），支持查看/取消/有效期管理
- **分类治理**：资源按分类树组织（category + category_owner），责任人管理

## 2. 核心功能

| 功能域 | 功能 | 说明 |
|--------|------|------|
| **权限资源** | 权限创建/关联 | 基于资源类型（API/事件/回调/数据）创建权限并关联 |
| **分类管理** | 分组 + 责任人 | 一级分组 CRUD、责任人配置（category_owner） |
| **订阅管理** | 订阅/撤回/取消 | 应用订阅权限，申请即代表申请权限关联资源 |
| **API 权限** | 目录查询/申请 | 消费方浏览 API 树、提交申请、查看状态 |
| **事件权限** | 目录查询/申请 | 消费方浏览事件树、提交申请、配置通道/地址/认证 |
| **回调权限** | 目录查询/申请 | 消费方浏览回调树、提交申请、配置通道/地址/认证 |
| **Scope 授权** | 用户授权 | 用户授权应用使用特定 scope，有效期管理 |
| **订阅数据迁移** | sync | 订阅数据迁移/回滚/紧急修复（老数据兼容） |

## 3. 设计真相

### 3.1 相关表

| 表名 | 说明 | 关键字段 |
|------|------|---------|
| `v2_category_t` | 分类表 | 一级分组，资源类型 |
| `v2_category_owner_t` | 分类责任人 | category_id → user_id |
| `v2_api_t` / `v2_event_t` / `v2_callback_t` | 资源主表 | API/事件/回调资源定义 |
| `v2_permission_t` | 权限表 | resource_type + resource_id（多态指向资源） |
| `v2_permission_p_t` | 权限属性 | parent_id → v2_permission_t.id |
| `v2_subscription_t` | 订阅表 | permission_id → 订阅权限（N:1） |
| `v2_user_authorization_t` | 用户授权表 | app_id 逻辑关联，scope + 有效期 |

| POST | /service/open/v2/apps/{appId}/callbacks/subscribe | 订阅回调 |
