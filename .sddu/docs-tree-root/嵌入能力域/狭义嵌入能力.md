## 1. 业务对象职责

| 属性 | 值 |
|------|-----|
| **对象名称** | 狭义嵌入能力 |
| **所属域** | 嵌入能力域 |
| **核心职责** | 构建三层架构的嵌入能力体系：平台面（ability 目录管理后台）→ 开放面（能力查询/订阅 + QianKun 微前端嵌入）→ API面（应用认证/成员查询/权限校验），解决能力预置硬编码、前端嵌入无规范、后端校验重复建设三大问题 |
| **业务边界** | MVP 非目标：ability 使用统计与分析、生命周期管理（下架通知/版本更新）、ability 与 API/Event 权限模型自动映射（通过 autoSubscribeAfterAbility 扩展点预留） |

## 2. 属性定义

> 三层子 Feature 聚合（EC-008 递归扫描）。

| 属性名 | 类型 | 必填 | 说明 |
|--------|------|:--:|------|
| ability 类型 | 实体 | ✅ | 中文名/英文名/中文描述/英文描述/图标/示意图/前端入口URL/排序（平台面 FR） |
| 能力目录查询 | 接口 | ✅ | 现有 GET /list 增强（开放面 FR-001） |
| 能力订阅 | 接口 | ✅ | 现有 POST / 能力扩展（开放面 FR-002） |
| 已订阅能力列表 | 接口 | ✅ | 现有 GET /subscribed 增强（开放面 FR-003） |
| autoSubscribeAfterAbility | 扩展点 | ✅ | 订阅后自动订阅关联能力的扩展点（开放面） |
| 用户角色查询 | 接口 | ✅ | 根据应用标识（平台应用ID / 外部 hisAppId）+ 用户账号查询角色（API面） |
